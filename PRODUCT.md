## Platform

web

## Stack

delegated: Vite + React + TypeScript single-page app with a build-time static JSON dataset (`web/public/data/`), generated by a Python scraping pipeline (`pipeline/`). Deployed as a static site (GitHub Pages or Netlify). Updates run on a GitHub Actions cron that re-executes the pipeline and commits refreshed data. Chosen by the user from offered options on 2026-08-01.

## Users

Researchers (PhD students, postdocs, faculty, industry labs) hunting for workshops to submit papers to. Their situation: they know their topic, they want a venue attached to a prestigious (A*/A) host conference, and they live against the submission deadline. Their job: discover relevant workshops across all A*/A conferences, compare deadlines and topics, and get to the workshop's call-for-papers before the deadline passes.

## Product Purpose

Conference deadline trackers (e.g. ai-deadlines, CCFDDL) cover main conferences, but workshops — where much early-career publication happens — are scattered across OpenReview, conference sites, and individual workshop pages. Workshop Finder unifies them: one searchable index of workshops co-located with A* and A rated conferences (ICORE2026 rankings), searchable by topic, field of research, and keywords, with submission deadlines front and center. Success means a researcher finds every relevant open workshop for their topic in under a minute, and trusts the data is fresh.

## Positioning

The only workshop index that is anchored to conference prestige (ICORE A*/A ranks) rather than listing everything indiscriminately, and that stays current by combining OpenReview's live venue API with direct conference-website scraping for the conferences that don't use OpenReview — no manual curation, no stale lists.

## Operating Context

Used around conference deadline seasons (heavy before NeurIPS/ICML/CVPR/ACL workshop deadlines). Users arrive with a topic in mind ("mechanistic interpretability", "robot manipulation"), scan deadline-ordered results, and click out to the call for papers. Data freshness is part of the product's promise: the dataset is regenerated on a schedule by CI, not edited by hand.

## Capabilities and Constraints

- Keyword search across workshop names, descriptions, and topics.
- Filters: field of research (ICORE FoR codes), host conference, conference rank (A*/A), deadline window, submission status (open/closed/TBA).
- Every workshop record links to its source (OpenReview venue page or conference/workshop website).
- Data sources: OpenReview API v2 (primary), conference websites (fallback for conferences not on OpenReview), ICORE2026 rankings portal (conference list + ranks + FoR codes).
- Constraint: fully static frontend; all data is pre-built JSON. No server, no auth, no user accounts.
- Constraint: scraping must be polite (rate-limited, cached) and resilient — a single failing source must not break the dataset.

## Evidence on Hand

- ICORE2026 rankings portal (https://portal.core.edu.au/conf-ranks/) — 825 ranked venues, ~7.5% A*, ~13% A, with acronyms, DBLP links, and FoR codes.
- OpenReview venue index (https://openreview.net/) — ~989 active venues including hundreds of workshops (e.g. "NeurIPS 2026 Workshop MLForSys"), plus an "Open for Submissions" list with due dates.
- Real workshop metadata (deadlines, websites, descriptions) is fetched live by the pipeline; the site must never fabricate deadlines — unknown values are shown as TBA.

## Product Principles

1. Prestige-anchored: every workshop is attached to an A*/A-ranked host conference; rank is always visible.
2. Deadline-first: the submission deadline is the primary sort and the most prominent metadata.
3. Never fabricate: missing data is labeled TBA/unknown, never invented; every fact links to its source.
4. Fresh by construction: data is regenerated on a CI schedule from live sources; staleness is visible ("last updated").
5. Search like a researcher: topics, fields, and keywords the way researchers actually phrase them.
